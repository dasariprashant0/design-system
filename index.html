Monoline

A small, accessible UI kit in monospace type, thin rules and square edges. Plain CSS with three themes and four accents. JavaScript and React are optional. Everything on this page is the real kit: switch the theme and accent in the sidebar.

Install

Pick the route that fits. All three give you the same classes.

1. A link tag. No build step

<link rel="stylesheet" href="https://dasariprashant0.github.io/design-system/css/monoline.css">
<script src="https://dasariprashant0.github.io/design-system/js/monoline.js" defer></script>  <!-- optional -->

Use monoline.min.css for production. For a frozen version, replace the host path with a commit: cdn.jsdelivr.net/gh/dasariprashant0/design-system@<commit>/css/monoline.min.css.

2. npm

npm install "monoline-ui@git+https://github.com/dasariprashant0/design-system.git#<commit>"

import 'monoline-ui/monoline.css';
import 'monoline-ui/monoline.js';                    // optional behaviours
import {Button, Field, useTheme} from 'monoline-ui/react'; // optional

3. Design tokens for other tools

tokens/tokens.json lists every colour, size and timing per theme and accent in the W3C design-tokens format. Feed it to Style Dictionary, Tokens Studio or a Figma variables import.

Theming

Two attributes on <html> control everything. A colour is never written in a component; it always comes from a token, so a theme change needs no extra CSS.

AttributeValuesDefault
data-themewarm, dark, midnightwarm. monoline.js picks dark when the system prefers it, and remembers a choice.
data-accentorange, green, blue, violetorange

A custom accent

Override four tokens per theme after the kit. It must pass three contrast rules, or text on and around it is hard to read: --accent-text on --background at least 4.5:1, --accent on --background at least 3:1, --on-accent on --accent at least 4.5:1.

:root, [data-theme="warm"] { --accent: #0E7A5F; --accent-text: #0B6A52; --accent-2: #E0A23A; --on-accent: #FFFFFF; }
[data-theme="dark"]        { --accent: #45C29C; --accent-text: #45C29C; --accent-2: #E0A23A; --on-accent: #06241C; }
[data-theme="midnight"]    { --accent: #5FD6B2; --accent-text: #5FD6B2; --accent-2: #FFC857; --on-accent: #06241C; }

The repo's npm run check tests every built-in theme and accent against these rules.

    When to use which

    TokenUse
    --foreground, --backgroundText and page. Never swap them for one-off greys.
    --mutedSecondary text. Already 4.5:1; never go lighter.
    --ruleEvery visible line. --border is for hairlines that may disappear.
    --accent, --on-accentFills and marks, and the text on them.
    --accent-textThe accent as text on the page background.
    --danger, --warning, --okLoss, attention, done. Always with a word or a shape too.

    Space and motion

    Space: 4px steps. Every margin, gap and padding

    Shape and depth

    Radius is 0. There are no shadows except the toast, and no gradients except the hatch. Depth comes from rules and space. Use --round only for a dot or radio.

    Motion

    App shell

    For apps: .shell holds a .side (264px) and a .main (padding 48px, max 1080px). A small window uses .window with .window-head and .window-body. For marketing sites use .topbar (see Navigation). This page is built on the shell.

    Buttons

    One solid button per view. Use real <button> or <a> elements.

    As a link

    Buttons are verbs: "Save", "Open folder", not "OK" or "Submit". Danger actions run, then offer Undo in a toast. Name icon-only buttons with aria-label.

    Segmented, for two to four options

    Fields

    Label above, hint or error below. The placeholder is never the label. Wrap each control in a .field and a <label>.

    Say what happened, then what to do: "Can't save. The folder is read-only. Pick another folder." Link the message with aria-describedby and set aria-invalid. Mark required fields with .field-required and the required attribute.

    What is Monoline?
    A small CSS kit with three themes and four accents, built on native elements.
    Do I need JavaScript?
    No. The accordion is a native details element. Tabs, dropdown dismissal and toasts use the optional monoline.js.
    Can I add my own accent?
    Yes. Override four tokens per theme and check the contrast rules.

    Accessibility

    The kit targets WCAG 2.2 AA. What it guarantees, and what stays with you:

    AreaKit doesYou do
    ContrastEvery theme and accent passes 4.5:1 for text and 3:1 for fills, tested by npm run check.Re-run the check after adding an accent.
    FocusA 2px accent ring on :focus-visible, drawn outside the control.Leave 8px between focusable things. Never remove the ring.
    KeyboardNative elements everywhere. Tabs support arrow keys, Home and End. Escape closes overlays.Tab through each screen before shipping.
    MotionAll animation stops under prefers-reduced-motion.Don't add looping motion.
    ColourStatus always pairs colour with a word or shape.Keep it that way in your own components.
    SemanticsClasses style native elements: button, label, fieldset, details, dialog, table.Use the element, then the class. Name icon-only buttons. Label every field.
    TouchButtons are at least 40px tall.Keep small buttons (.btn-sm) off touch-first screens.
    Zoom and reflowLayouts wrap and stack at narrow widths.Test at 200% zoom.

    Do and don't

    Do

    • Use tokens and kit classes
    • Reach for the native element first
    • One solid button per view
    • Offer Undo instead of confirming
    • Check in all three themes at 900px

    Don't

    • Raw colours, font sizes or spacing in a screen
    • Border radius, shadows, gradients or blur
    • Icon fonts or a second UI library
    • A second accent in one project
    • Centred body text
